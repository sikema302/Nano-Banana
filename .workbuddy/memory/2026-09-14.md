## 香蕉(uselg/flux 渠道)改为异步图片任务 API

- 调研 uselg.top(FluxPort)文档(数据接口 `/api/v1/pricing/public`,文档内容在前端 chunk `ApiDocsView` 内):该站香蕉=`gemini-3.1-flash-image-preview`/`gemini-3-pro-image-preview`,文档标称走 Gemini 原生 `generateContent`;异步任务(202+轮询 `/v1/images/tasks/{id}`,提交体带 `"async": true`)是 GPT/Grok 图片的 `/v1/images/generations` 链路。之前 flux-banana 优先打 `:streamGenerateContent?alt=sse`,所以后台显示"流式"。
- 改造 `server/flux-banana.ts`:`generateFluxBanana` 现在**优先走 OpenAI 兼容异步图片任务 API**(文生图 `POST /v1/images/generations`、参考图 `POST /v1/images/edits` multipart,均带 `async:true`,Bearer 鉴权,轮询优先 `status_url?view=summary`,资产优先 `assets[].signed_url`);若网关对该模型/端点返回 404/405/422/501 或 400+「不支持」类消息,自动回退原 Gemini 原生协议(streamGenerateContent→generateContent)。轮询/下载同源请求同时带 Bearer 与 x-goog-api-key。
- 复用 `schat-image.ts` 的 `schatImageSize` 做 OpenAI size 映射;审核类 400 仍标记 safeToFallback=false。
- 更新 `server/flux-banana.test.ts`:新增异步提交格式、edits multipart、signed_url、模型被拒回退等用例;原生流式用例前置 404 走回退路径。全套 156 个服务端测试通过。
- 注意:uselg 是否真的允许 gemini 图片模型走 `/v1/images/*` 未经线上验证(本地无可用 Key);若不支持会自动回退原生协议并打 `[flux-banana]` warn 日志,部署后需观察日志确认实际路径。
