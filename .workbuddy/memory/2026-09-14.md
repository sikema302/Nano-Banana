## 香蕉(uselg/flux 渠道)改为异步图片任务 API

- 调研 uselg.top(FluxPort)文档(数据接口 `/api/v1/pricing/public`,文档内容在前端 chunk `ApiDocsView` 内):该站香蕉=`gemini-3.1-flash-image-preview`/`gemini-3-pro-image-preview`,文档标称走 Gemini 原生 `generateContent`;异步任务(202+轮询 `/v1/images/tasks/{id}`,提交体带 `"async": true`)是 GPT/Grok 图片的 `/v1/images/generations` 链路。之前 flux-banana 优先打 `:streamGenerateContent?alt=sse`,所以后台显示"流式"。
- 改造 `server/flux-banana.ts`:`generateFluxBanana` 现在**优先走 OpenAI 兼容异步图片任务 API**(文生图 `POST /v1/images/generations`、参考图 `POST /v1/images/edits` multipart,均带 `async:true`,Bearer 鉴权,轮询优先 `status_url?view=summary`,资产优先 `assets[].signed_url`);若网关对该模型/端点返回 404/405/422/501 或 400+「不支持」类消息,自动回退原 Gemini 原生协议(streamGenerateContent→generateContent)。轮询/下载同源请求同时带 Bearer 与 x-goog-api-key。
- 复用 `schat-image.ts` 的 `schatImageSize` 做 OpenAI size 映射;审核类 400 仍标记 safeToFallback=false。
- 更新 `server/flux-banana.test.ts`:新增异步提交格式、edits multipart、signed_url、模型被拒回退等用例;原生流式用例前置 404 走回退路径。全套 156 个服务端测试通过。
- 注意:uselg 是否真的允许 gemini 图片模型走 `/v1/images/*` 未经线上验证(本地无可用 Key);若不支持会自动回退原生协议并打 `[flux-banana]` warn 日志,部署后需观察日志确认实际路径。

## 定论:uselg 不支持香蕉走异步 Images 接口

- 用户用真实 key 探测 `POST https://api.ai-media.vip/v1/images/generations`(banana 模型)返回 `{"error":{"message":"Images API is not supported for this platform","type":"not_found_error"}}` → 该网关只给 GPT/Grok 图片开异步接口,Gemini 图片(香蕉)只能走 `/v1beta/...` 原生协议,控制台显示"流式"是平台固有限制,改不了。
- 优化 `server/flux-banana.ts`:新增 `IMAGES_API_UNSUPPORTED_BASES`(Set,按 baseUrl 记忆)+ `resetFluxBananaImagesApiMemory()`,探测到不支持后记住结论,后续请求直接走原生,消除每张图一次注定 404 的探测 + warn 日志噪音。
- 测试:新增「记住结论跳过探测 / 换网关仍探测」用例,`beforeEach` 重置记忆防串测。本地 tsc 0 error + 157 测试全绿。待用户 commit + push。

## 香蕉最终改为纯 Gemini 原生 generateContent(非流式)

- 用户给出明确接口契约,要求香蕉走 `POST /v1beta/models/{model}:generateContent`(非流式,不要 `streamGenerateContent?alt=sse`),请求头 `x-goog-api-key` + `Content-Type: application/json`,请求体 `contents[{role,parts[{text}]}]` + `generationConfig.responseModalities=["TEXT","IMAGE"]` + `imageConfig{aspectRatio,imageSize}`;若返回 202 异步任务则保存 `task_id`/`status_url` 轮询,不重复提交。
- 彻底重写 `server/flux-banana.ts`:删除 OpenAI 兼容 `/v1/images/generations`+`/v1/images/edits` 提交路径、`IMAGES_API_UNSUPPORTED_BASES` 记忆机制、`imagesApiUnsupportedError`/`isImagesApiUnsupported`、`resetFluxBananaImagesApiMemory`、SSE 解析(`readSsePayloads`)与 `schatImageSize` 依赖。提交统一走 `submitViaGeminiNative`(generateContent,非流式)。
- 轮询保留:202 后按 `status_url`/`poll_url`/`result_url` 优先,否则用 `task_id`/`id`/`request_id` 自行拼接 `/v1/images/tasks/{task_id}`(新增 `taskQueryUrl`);资产优先 `assets[].signed_url`,同源轮询/下载同时带 Bearer + x-goog-api-key。
- 更新测试:删掉 OpenAI edits/multipart、流式 SSE、记忆探测等用例,改为断言 generateContent 端点、x-goog-api-key 头、inlineData 读取(含 snake_case inline_data)、无 status_url 时按 task_id 拼接轮询。本地 tsc 0 error + 153 测试全绿 + vite build 通过。待用户 commit + push。
