## 排查「minimax 的 key 没配置吗」

- 项目里**没有独立的 MiniMax key**。minimax = 视频渠道品牌名（minimax_h3-768p/1080p/2K），
  走 Uselg/FluxPort `https://api.ai-media.vip/v1/videos`，由单个 `USELG_VIDEO_API_KEY` 驱动
  （`server/index.ts:696`；未配置时 `index.ts:2259-2260` 抛「视频渠道尚未配置 API Key（USELG_VIDEO_API_KEY）」）。
- **部署链路从不写这个变量**：`.github/workflows/deploy-production.yml` 的 secrets 只有
  VISIONARY_NANO_LITE / FLUX_BANANA / SCHAT / USSELG_STANDARD_KEY + USSELG_HD_KEY / R2_* / DEPLOY_SERVER_PASSWORD；
  `deploy.sh` 只写上面这些 + 并发/资源参数。→ 线上 `.env.local` 大概率没有 `USELG_VIDEO_API_KEY`。
  本地 `.env.local:29` 有值，所以本地能跑、线上不能。
- **失败在后台「生成记录」里查不到**：`server/video-generation.ts` 的 provider 没有 `onAttempt` 回调，
  只在成功后写一条诊断记录（`tryRecordGenerationRequest`，`index.ts:10106`），失败只释放预留积分、不落库。
  只能看 pm2 日志。
- 生产：`/var/www/nano-banana`，pm2 进程 `nano-banana`，改 env 后需 `pm2 restart nano-banana --update-env`。
- 待用户决定修法：①服务器 `.env.local` 手工追加（deploy.sh 只删白名单并发变量，手工值能存活）；
  ②加 GitHub Secret + workflow 打包 `.secrets/uselg-video-env` + deploy.sh 带空值保护写入。

## 已实施「方案②」（用户提供 key，选正规路）

- `.github/workflows/deploy-production.yml`：
  ① env 块加 `USELG_VIDEO_API_KEY: ${{ secrets.USELG_VIDEO_API_KEY }}`（第 25 行，单 S，与服务端 env 同名）；
  ② 打包段加带空值保护的 `.secrets/uselg-video-env` 生成（第 83 行）。
- `deploy.sh`：`uselg-env` 块之后新增 `uselg-video-env` 块（137-143 行），
  `grep -v '^USELG_VIDEO_API_KEY='` 去重后写入 `.env.local`；空文件 `-s` 判断跳过，不会冲空手工值。
- **注意：secret 名是 `USELG_VIDEO_API_KEY`（单 S），与 `.env.example`/`server/index.ts:696` 一致；**
  图片渠道仍用 `USSELG_`（双 S），两者本就是项目里既有命名差异。
