# 2026-11-03

## 视频生成「超时丢单」修复（治本 + 兜底）

**背景**：用户报告 junli 上游已扣费（90）但本地未扣客户、未交付。根因：视频
`minimax-h3-optimized`（走君临渠道）上游耗时 1599s > 后端超时 20 分钟
（`USELG_VIDEO_TIMEOUT_MS`），后端 `AbortController` 掐断 → 本地判 `stage=upstream`
失败、只释放预留不扣客户；但上游继续生成并计费 → 净亏且视频没交付。

**改动**（三步验证 tsc+test+build 全过，216 测试）：
1. `server/generation-reconciliation.ts`：`GenerationResumeKind` 加 `'uselg-video'`。
2. `server/video-generation.ts`：
   - `UselgVideoOptions` 加 `resumeTask?: { taskId: string }`，支持跳过提交直接轮询+下载（绝不二次计费）。
   - 整体超时且 `submittedTaskId` 已就绪时抛 `indeterminateTaskError`（kind='uselg-video'，
     channelId=provider、sourceModel），供上层续查。
3. `server/index.ts`：
   - `USELG_VIDEO_TIMEOUT_MS` 20→35 分钟；内网 fetch `AbortSignal.timeout` 21→40 分钟（须 > 视频超时）。
   - 视频 handler 顶层提升 `persistedReferenceImages`/`createdAt`。
   - 新增 `videoReconciler`（复用 `createGenerationReconciler` 泛型）+ `resumeIndeterminateVideo`
     + `recordReconciledVideoHistory` + `failPendingVideoReconciliation`；
     单次续查探测窗口 `VIDEO_RECONCILE_PROBE_TIMEOUT_MS=5min`（避免慢视频阻塞 tick）。
   - 视频 `/api/video` catch 块：`resumeFromError` 命中 uselg-video 时登记对账、返回 202
     `indeterminate`、预留转交对账器；迟到成功补扣+补交付，终局失败释放预留。
   - `runVideoGenerationJob` 识别 202 indeterminate 时保持 processing（不误判失败）。
   - `setInterval` 里同时 tick `generationReconciler` + `videoReconciler`。
4. `server/video-generation.test.ts`：补 resume 跳过提交 + 超时抛可续查错误两个测试。
