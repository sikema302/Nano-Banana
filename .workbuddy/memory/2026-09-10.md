## 排查：Flux 上游成功但用户侧没拿到图
- 现象：上游（api.ai-media.vip，key invite-144d）后台显示 3 笔 4K 图生图成功（81~126s，扣 24~34 积分/笔），但 PIXORY 侧用户没拿到图。
- 代码分析（server/flux-banana.ts + index.ts）发现 4 个"上游已出图但判失败"断点，全部 safeToFallback=false → 不换渠道直接 IMAGE_MODEL_BUSY：
  1. 长耗时（80~126s）同步等待时连接被中间层掐断（terminated），requestSent=true 导致不可回退（最可能）；
  2. 成功 payload 结构 generatedImage() 解析不到（只认 candidates.parts.inlineData / assets[]）→ "Flux image task completed without a downloadable image"；
  3. materializeImage() 下载结果图失败（临时 URL 过期/空文件/content-type 非图片）；
  4. 首响应只有 task_id 无 status/poll URL → "Flux image provider returned no image"。
- 根因落库位置：generation_requests.error_detail（管理后台生成记录可见）；服务器日志关键词 `[image-channel]` / `[public-async]`。
- 部署：VPS root@23.141.172.73，/var/www/nano-banana，pm2 进程名 nano-banana，域名 pixory.top。本机未存 SSH 密码。
- 注意：pm2 logs 是流式的，接 grep 管道会挂住"没反应"，应直接 grep ~/.pm2/logs/ 下的日志文件。
- 待办：拿到 error_detail/日志后定位具体断点并修复（断连可安全重试、兼容更多成功响应结构、失败时打印原始 payload）。
