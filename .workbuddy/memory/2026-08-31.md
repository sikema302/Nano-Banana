## 排查 admin 后台「请求结果」列 `fetch failed` / `terminated` 报错

- 现象：admin 生成记录列表里 `请求结果` 列显示 `fetch failed`、`terminated` 等模糊文本，无法定位根因。
- 根因：
  - `fetch failed` 是 Node 内置 fetch/undici 网络层失败时统一抛出的 message，真实 code（ECONNRESET / UND_ERR_SOCKET 等）在 `error.cause` 里。
  - 写库时只取了 `error.message`（`imageErrorText` / `errorText`），丢了 `cause` 和 `status`。
  - `terminated` 长耗时（150–180s）才出现，多为上游/网关中途掐断连接或上游 HTTP 响应体里就是 `terminated`。
- 修复（2 个文件）：
  - `server/image-provider-router.ts`：新增 `errorDetailText(error)`，把 `message + HTTP status + cause` 拼起来；`callFallback`、`generate` 的 `reportAttempt` 改用 `errorDetailText`。
  - `server/index.ts`：新增 `imageErrorDetail(error)`（同样拼 status + cause），`recordImageChannelAttempt` 的 `errorMessage` 改用 `imageErrorDetail`。
- 验证：`npx tsc --noEmit` 通过；`image-provider-router.test.ts`（25 用例）、`public-image-error.test.ts`（31 用例）全部通过。

## 关键结论（长期）

- 错误展示链路：用户端走 `publicImageErrorMessage`（public-image-error.ts，友好中文）；admin 后台走 `generation_requests.error_detail`（原文，App.tsx:4951 优先展示 errorDetail 而非 resultMessage）。
- `sanitizeExternalErrorMessage`（index.ts:4636）只清洗 resultMessage，不作用于 errorDetail。
