## 后台用户列表新增「重置密码」按钮（commit ed5c7f7，本地未 push）

- 需求：用户列表操作列（积分记录/充值/扣积分/删除）里加「重置密码」，密码统一重置为**该用户的用户名**。
- 后端新增 `POST /api/admin/users/:userId/reset-password`（`requireAuth, requireAdmin`）：
  - SQLite：先 `withReadDb` 定位用户——`users u LEFT JOIN user_migrations m ON m.legacy_user_id = u.id
    WHERE CAST(u.id AS TEXT)=? OR m.supabase_user_id=?`（userId 可能是迁移后的 supabase id），
    再在**事务外** `bcrypt.hash(username, 10)`（避免同步哈希阻塞事件循环，沿用现有约定），最后 `withWriteDb` 写回。
  - Supabase：`db.findUserById` + `db.updateUserPassword`（supabase-db.ts 已有这两个函数）。
- 前端 `src/App.tsx`（AdminView 组件）：新增 `resettingPasswordUserId` 状态 + `handleResetPasswordUser`（confirm 二次确认）
  + 紫色「重置密码」按钮；`handleResetAdminUserPassword` 主逻辑 + `onResetPassword` prop 透传。
  - 与充值/扣积分/删除互斥禁用（互相加 `resettingPasswordUserId === item.userId`）。
  - API-key 用量行（`isApiKeyUsage`）不显示该按钮。
- `src/lib/api.ts` 新增 `resetAdminUserPassword(userId)`。
- 验证：tsc ✓ / 218 测试 ✓ / vite build ✓。

## 背景：密码存储不可反查

- 密码为 `bcrypt.hash(pwd, 10)` 单向哈希，`bcrypt.compare` 校验，**无法反查明文**（含站长）。
- 本地 dev 库 `data/app.sqlite` 的 users 表只有 `admin` 一个用户；`matenghan` 在生产库。
- 生产 SSH 仍被按来源 IP 拦截（见历史记忆），需用户在宝塔终端操作或放开访问。
- 生产部署路径 `/var/www/nano-banana`，主库 `data/app.sqlite`，PM2 进程名 `nano-banana`。
