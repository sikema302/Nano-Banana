## 网站慢 + 下载图片慢排查

- **首屏慢根因（已修）**：生产 `index.html` 有 render-blocking 的 Google Fonts
  `<link rel="stylesheet" href="fonts.googleapis.com/css2?...Cormorant+Garamond...Manrope...">`，
  国内被墙 → 浏览器阻塞首屏渲染几十秒（白屏）。
  这两个字体项目里根本没被消费（`--font-serif` 只有定义、无 class 使用；Manrope 完全无引用），纯负担。
  已删 index.html 3 行 + `src/index.css` 的 `--font-serif` 去掉 Cormorant Garamond；build 通过，commit `5f6ac34`（未 push）。
- **源站位置纠正**：`23.141.172.73` = 香港（AS979 NetLab Global），不是美国；pixory.top 走 Cloudflare，图片在 Cloudflare R2。
- **图片下载链路**：展示（缩略图/预览）直连 R2 公开 URL；**下载走服务器中转** `/api/user/assets/download`
  （`src/lib/api.ts` 登录用户走 `nativeFormDownload` 表单提交），服务端是流式转发（`Readable.fromWeb(upstream.body).pipe(res)`，index.ts:10472），
  不是整图读内存。慢因 = 数据多跳（R2→香港源站→Cloudflare→用户）+ 2K/4K 大图 + Cloudflare 国内路由。
- 服务器本身空闲：cpu 0.4% / mem 36% / eventLoop 20ms / 队列 active 1，非过载。
- **用户已确认**：看图 + 下载 + 接口全都慢，且是「最近才变慢」。
  → 结论：共同瓶颈是 **Cloudflare**（网站 pixory.top、图片 R2、API 全部挂 Cloudflare）。
  Cloudflare **大陆无边缘节点**，国内访问需跨境到香港/新加坡节点，晚高峰出口拥堵/丢包，属周期性线路劣化。
  服务器（香港源站 AS979）空闲健康（cpu 0.4%），非过载。
- 解法方向（待用户选云厂商）：① 图片套国内/亚太优化 CDN（收益最大）；② 网站+API 用 Cloudflare 优选 IP 或换国内 CDN（需备案）；
  ③ 短期确认是否晚高峰更明显。Google Fonts 修复（commit 5f6ac34）需 push 部署。
