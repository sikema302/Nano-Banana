# 2026-10-30

## minimax-h3-optimized 报 HTTP 400 invalid request body（用户截图排查 + 修复）

### 现象
后台生成记录：`video / 768p / 3s`，渠道显示 `Uselg · minimax-h3-optimized`，
`stage=Video returned HTTP 400: {"detail":"invalid request body"}`，199ms 快速失败。

### 根因（多重，全部按君临官方文档核实）
君临文档有 Markdown 版，可直连抓取（**重要，以后查君临契约先看这里**）：
- `https://img.junliai.org/docs.md?page=quickstart`（接入准备/base URL）
- `https://img.junliai.org/docs.md?page=video`（通用 /v1/videos 全参数表）
- `https://img.junliai.org/docs.md?page=minimax`（H3 优化版专页）

1. **时长下限**：文档明确「H3 优化版支持 4–15 整数秒、768P；720P 按兼容规则对应 768P」。
   10-28 为 uselg minimax-h3（3-15）把全局 `VIDEO_MIN_SECONDS` 改成 3，导致前端可选 3 秒 →
   提交 3s 被上游 400 拒绝。**这就是截图这条的直接原因。**
2. **媒体字段格式不同**（更隐蔽，有参考素材时才会炸）：
   - uselg：`reference_images: [{ url }]` 对象数组，无 reference_mode
   - 君临：`reference_images: [url]` **字符串数组**，且素材参考必须带 `reference_mode: "asset"`
   - 音频字段名两边都是 `reference_audios`（君临另有 audio_reference 别名）
3. **分辨率大小写**：君临示例用大写档位 `768P`，uselg 用小写 `768p`。
4. **下载地址**：君临完成态直接在响应里给 `url`（自带临时凭证，最长 24h），
   优先用它；uselg 仍走 `/v1/videos/{id}/content`。

### 改动
- `src/lib/model-credit-config.ts`：`VideoModelSpec` 新增 `minSeconds`/`maxSeconds`
  （minimax-h3/grok/768p = 3/15，**optimized = 4/15**）；新增 `getVideoSecondsRange()`。
- `server/video-generation.ts`：`normalizeVideoSeconds(value, modelId?)` 按模型范围钳制；
  `UselgVideoOptions.provider?: 'uselg' | 'junliai'`（默认 uselg）→ 分支构造请求体
  （junliai：字符串数组 + reference_mode=asset + resolution 大写）；
  `VideoTaskPayload` 加 `url`/`video_url`，完成态优先直链下载（不附 Authorization）。
- `server/index.ts`：`callVideoGeneration` 传 `provider: useJunliai ? 'junliai' : 'uselg'`；
  3 处 `normalizeVideoSeconds` 调用补 modelId（含 getVideoCredits、预扣费、实际生成）。
- `src/App.tsx`：秒数选项按 `getVideoSecondsRange(videoModel)` 动态渲染；
  `selectVideoModel` 切模型时把秒数钳制到新范围。
- `server/video-generation.test.ts`：新增 2 个君临格式用例（字符串数组/asset/768P/直链下载、
  无素材时不带 reference_mode）+ optimized 4-15 秒钳制断言。
- `.env.example`：视频渠道注释更新（原来还写着已下线的「全参MinimaxH3」）。

### 验证
三件套全过：`tsc --noEmit` 0 错、`tsx --test` **214 通过 / 0 失败**、`vite build` 成功。
本地 `.env.local` **没有 JUNLIAI_API_KEY**（只有生产有），所以未做真实上游实测；
部署后第一次 4 秒生成即可验证。

### 备注
- 后台生成记录的 `provider` 字段对视频一律写死 `'Uselg'`（server/index.ts 约 10404 行），
  所以优化版记录也显示 `Uselg · minimax-h3-optimized`，实际走的是君临。
  若以后要区分，可改成按 modelId 写 `Junliai`。
- 优化版计费仍按秒单档（`video.minimaxOptimized.perSecond`），与分辨率无关。
