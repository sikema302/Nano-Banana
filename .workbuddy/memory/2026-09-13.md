## 修复 GPT-image-2.5 点击生成瞬间报错「当前模型太拥挤了」

**现象**：新接入的 GPT-image-2.5-Flare / Sunburst 点击生成瞬间报错「当前模型太拥挤了，请稍后重试或试试其他模型（本次未扣除积分）」，且上游接口完全没被调用。

**根因**：`server/index.ts` 的 `callConfiguredImageChannel` 里，渠道分发只有 `input.modelId === 'gpt-image-2'` 的分支（原 5253 行）。GPT-image-2.5-* 没有任何分支，导致 `image2Routes` 里所有渠道（junliai-economy / junliai-firefly / uselg / visionary）都直接落到末尾 `throw new Error('Image channel X is unavailable')`（safeToFallback=true），**一次上游 HTTP 都没发出**。最终 `callImageGeneration` 兜底抛 `IMAGE_MODEL_BUSY`，映射为「当前模型太拥挤了」。

**修复**（server/index.ts）：
1. 新增 `isGptImage2Family(modelId)`：判断 `gpt-image-2` / `GPT-image-2.5-Flare` / `GPT-image-2.5-Sunburst`。
2. 新增 `resolveJunliaiUpstreamModel(channelId, modelId, imageSize)`：把 image2Routes 渠道映射到 junliai 上游模型名：
   - GPT-image-2.5-Flare：1K → `gpt-image-2.5-flare`（junliai-economy），2K/4K → `firefly-gpt-image-2.5-flare`（junliai-firefly）
   - GPT-image-2.5-Sunburst：1K → `gpt-image-2.5-sunburst`，2K/4K → `firefly-gpt-image-2.5-sunburst`
   - GPT-image-2：junliai-economy → `gpt-image-2`，junliai-firefly → `firefly-gpt-image-2`（原逻辑不变）
3. `callConfiguredImageChannel` 的 `if (input.modelId === 'gpt-image-2')` 改为 `if (isGptImage2Family(input.modelId))`，并把硬编码 upstreamModel 改为调用 `resolveJunliaiUpstreamModel`。
4. `schat-gpt-image-2` 分支加 `&& input.modelId === 'gpt-image-2'` 限制（2.5 不走 schat 的 gpt-image-2 模型）。
5. 顺带修复 quality 参数传递：4 处 `modelId === 'gpt-image-2' ? normalizeGptQuality(...)` 改为 `isGptImage2Family(modelId)`，让 2.5 的 2K/4K 质量（auto/low/medium/high）正确传递与计费。

**验证**：`npx tsc --noEmit` 通过。

**注意**：本地 `.env.local` 未配置 JUNLIAI_API_KEY（空占位符），所以本地测试时 GPT-image-2.5 会走 junliai → 抛 safeToFallback → fallback uselg/visionary 也失败。修复后至少会正确发起上游请求（与 GPT-image-2 行为一致）；真正出图需在配了 JUNLIAI_API_KEY 的环境验证。

## 修复 GPT-image-2.5 结果展示仍显示「GPT-image-2」

**现象**：选了 2.5 生成后，历史记录/预览卡片里模型名仍显示「GPT-image-2」，点击编辑回填的模型也变成 gpt-image-2。

**根因**：`src/App.tsx` 两处硬编码把 2.5 归并成 2：
1. `displayModelName()`（约 349 行）：`probe.includes('gpt-image')` 命中所有 gpt-image 系列（含 2.5），统一返回 'GPT-image-2'。
2. `startEditSession()`（约 5843 行）：`normalizedName.includes('nano banana')` / `seedream` 都不命中 2.5，落到兜底 `'gpt-image-2'`。

**修复**：
1. `displayModelName` 在 gpt-image 判断前加 `gpt-image-2.5` 分支：含 sunburst → 'GPT-image-2.5 Sunburst'，否则 → 'GPT-image-2.5 Flare'。
2. `startEditSession` 增加 2.5 分支，按 sunburst/flare 回填 `GPT-image-2.5-Sunburst` / `GPT-image-2.5-Flare`。

**验证**：`npx tsc --noEmit` 通过。

**教训**：接入新模型时，前端所有 `modelId === 'gpt-image-2'` 或 `includes('gpt-image')` 的硬编码判断都要排查，容易漏掉展示层/回填层的归并逻辑。

## 修复 GPT-image-2.5-Flare / Sunburst 不显示「99%成功率」标签

用户反馈：选择 GPT-image-2.5 时不需要展示「99%成功率」绿色标签。已在 `src/App.tsx` 的 `getModelSuccessRate` 中去掉 GPT-image-2.5-Flare / Sunburst 分支，只对 GPT-image-2 显示。

## 收藏区 SidePanel 三项 UI 改造

**改动文件**：`src/App.tsx`

1. **字体变大**：prompt `text-xs`(12px) → `text-sm`(14px)；时间 `text-[11px]` → `text-xs`；按钮 `text-[11px]` → `text-xs`。
2. **图片固定 + 下方独立横滑**：`article` 拆成上下两层：
   - 上层是图片（`h-20 w-full`），固定不动。
   - 下层是 prompt + 时间 + 按钮，套 `overflow-x-auto` 横滑容器，prompt 加 `whitespace-nowrap`。
   - 卡片之间依然可以横向滚动浏览更多图片，但单个卡片右滑时只有下方文字区域跟随滑动，图片保持稳定。
3. **批量下载**：
   - SidePanel 新增 `onBatchDownload?: (items: SavedImage[]) => void` prop。
   - 当传 `onBatchDownload` 时，每张图右上角出现勾选圆点（仅登录用户可见），点击切换选中。
   - 顶部 action 按钮文字根据状态变化：「下载」（无选中）→「下载 (N)」（选中 N 张）。点击行为：无选中走 `onAction`（下载第一张），有选中走 `onBatchDownload(选中的)`。
   - 父组件新增 `downloadBatchImages()`：用 `setTimeout(item, index * 250)` 错开下载，避免浏览器把并发下载判定为弹窗广告拦截。
   - 收藏区（主视图 + admin 视图）两处都接上 `onBatchDownload={downloadBatchImages}`。备份区/丢弃区不传，保持原单动作行为。
4. 顶部图标库新增 `Check`（lucide-react）用于勾选态显示。

**验证**：`npx tsc --noEmit` 通过。前端 vite 已重启，访问 http://localhost:3000 即可看到效果。
